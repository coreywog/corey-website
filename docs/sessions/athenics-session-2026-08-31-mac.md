- **Recurring-transaction auto-detection**, from scratch — the manual subscription-tagging UI the request assumed still existed (`RecurringSubscriptions.tsx`) was already deleted in the Data Hub rework, and there was no recurring/subscription field anywhere in the schema. Also found `lib/finance.ts` already has `computeRecurringSubscriptions` (dead code, no longer called by anything) — that one's scoped to a curated "subscriptions/fitness" category allowlist for a "worth cancelling" view; deliberately left alone rather than reused, since this ask was for detection across *every* merchant/category. Confirmed with Corey before building: surfaces as a new Data Hub panel, and persists (not recomputed fresh every load).
  - **Schema**: new `RecurringGroup` model (merchant label encrypted like `Transaction.description`, interval, confidence, status) + `Transaction.recurringGroupId`. Migration `20260901015538_add_recurring_groups` applied — purely additive (new table + nullable column), no data touched.
  - **Algorithm** (`lib/recurringDetection.ts`): groups un-grouped spending transactions by normalized merchant (reuses `normalizeMerchantName`), needs ≥3 charges, classifies the median day-gap into weekly/biweekly/monthly/yearly (with tolerance), scores confidence as a 60/40 weighted blend of gap regularity and amount regularity (both as inverted coefficient-of-variation, so it's scale-independent — a $10 charge wobbling $0.50 and a $1500 charge wobbling $75 score the same). Below 0.35 confidence isn't surfaced at all. A "dismissed" group is never touched by a later run — see the schema comment; a "confirmed"/"pending" group gets newly-imported matching transactions linked but its status left alone.
  - **Sanity-checked the scoring math** against synthetic cases in an isolated scratch script (no DB) before wiring it up: exact-monthly and exact-yearly charges scored 0.97, biweekly 0.99, variable-amount weekly groceries 0.86, random one-off purchases and only-2-charges both correctly returned null (no pattern).
  - **API**: `GET /api/finance/recurring` (list by status), `POST /api/finance/recurring/detect` (run a scan), `PATCH /api/finance/recurring/[id]` (confirm/dismiss/reset to pending).
  - **UI**: `RecurringPanel.tsx` in the Data Hub's Finance tab — "Scan for recurring charges" button, pending groups with interval/confidence badges, average amount, charge count, last-charged date, Confirm/Dismiss actions.
